请停止用 AI 垃圾淹没我们的项目来提供你的简历
2026 年 6 月 30 日 作者：尼尔
对开源项目的成功贡献是一种货币。

 GitHub 特别以多种方式鼓励这一点：在存储库页面上显示贡献者的头像，通过活动源向关注者显示您的贡献，以及在您的个人资料的活动图表上标明每天的贡献。

潜在的招聘经理经常会注意到这一点。

招聘人员经常通过这种方式寻找和筛选候选人。

如果您是一名正在寻找工作的软件开发人员（无论是现有的还是有抱负的），调整这些信号通常可以为您带来优势。

作为一名开源维护者，去年外部贡献模式的变化非常明显。

我们更有可能收到拉取请求而不是问题。

如果我们确实收到问题，它们通常会附带人工智能生成的分析。

我们收到的安全漏洞报告比以往任何时候都多得多，而且通常它们甚至还附有人工智能生成的修复建议。

我毫不怀疑其中一些贡献来自那些真正对我们所做的事情感兴趣的人，但我愤世嫉俗的部分认为，其中很大一部分是人们意识到人工智能可以用来博弈 GitHub 以谋取自己的利益。

现在很容易要求 Claude 生成一个有趣的开源项目列表，然后要求 Claude 发现其中的一些问题，然后要求 Claude 提出一些 PR 来修复这些问题。

你甚至不必使用这些项目或关心它们，但你可以很容易地给局外人制造出你关心的错觉，或者你发现了问题，或者你投入了时间来解决它。

在互联网上，没有人知道你是一只狗，但在法学硕士的帮助下，你可以毫不费力地在 GitHub 个人资料上夸大你的人类能力。

最近，一位贡献者从 2018 年底到几周前几乎没有在 GitHub 范围内做出任何贡献，据我们所知，之前也没有参与过我们的项目，但他提出了三个单独的 PR 来纠正评论中的拼写和语法错误。

 Claude 进行了修复，大概编写了 PR 描述，甚至代表用户签署了提交，然后将其共同作者身份插入到提交消息预告片中。

也许它甚至自己打开了 PR，谁知道呢。

我很想知道提示是否是“去寻找问题”，或者是否出于某种原因特别关注拼写和语法问题。
