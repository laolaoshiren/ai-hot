刚刚，‌FreeCORE：TrueNAS 衍生分支，在 FreeBSD 系统上维护与之深度整合的虚拟化、Jails 容器与 OpenZFS 文件系统‌

⚡ 一句话看懂：刚刚，‌FreeCORE：TrueNAS 衍生分支，在 FreeBSD 系统上维护与之深度整合的虚拟化、Jails 容器与 OpenZFS 文件系统‌。来源：InfoQ AI。

多年来，TrueNAS CORE 一直是开源存储设备的公认标准，它基于 FreeBSD 和 OpenZFS 构建，其稳定性被一些人誉为“坚如磐石”。

然而，当上游维护者 iXsystems 将其工程资源完全转向基于 Debian Linux 的 TrueNAS SCALE 项目时，现有用户便面临着架构被弃用的困境。

作为一个新推出的、由社区驱动的衍生项目， FreeCORE 将 TrueNAS CORE 13.3 的基线直接升级至 FreeBSD 15.0，有望填补这一空白。

图片来源：由 Gemini 基于 https://freecore.org 页面的信息生成 FreeCORE 15.0-U1 目前处于稳定状态，并提供了一条从 13.3 基础版本无缝升级至 15.0 的就地升级路径。

按照计划，下一版本将是 15.1。

从技术角度来看，该分支具有重要的意义，因为它恢复了深度集成的虚拟化生态系统——特别是 FreeBSD Jails 、原生插件和 bhyve 虚拟机——在上游 Linux 转换期间，这些功能曾经被标记为已过时。

通过保留这些功能，FreeCORE 直接满足了那些围绕 FreeBSD 生态系统构建了庞大基础设施的管理员的需求。

这种架构上的差异突显了 FreeBSD Jails 与 Linux 容器在安全模型上的显著差异。

FreeBSD Jails 提供了深度集成的操作系统级内核隔离，其成熟度之高，使得许多存储工程师认为，与 TrueNAS SCALE 中广泛使用的基于命名空间的 Linux 容器（LXC/Docker）隔离相比，它能提供远为优越的安全边界。

此外，存储管理员必须仔细权衡 OpenZFS 原生加密的现状。

正如社区讨论中所指出的那样，目前原生加密缺乏专职的上游维护者，这导致一些专业人士倾向于使用 Linux LUKS，除非原生 ZFS 功能是绝对的运行要求。
